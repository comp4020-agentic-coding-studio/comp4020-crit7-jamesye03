# Crit 7

**What was the breakthrough that moved the work forward?**

The breakthrough wasn't a technical trick, it was noticing that my own
feedback kept staying abstract when it needed to be concrete. Saying "courses
and my timetable shouldn't be tucked in a small corner" doesn't tell an agent
what to build; saying "move them to a centred, prominent nav bar" does. Once I
started translating my own dissatisfaction — the catalog feels thin, the
timetable sidebar clips content — into exact UI specifications (a long
clickable rectangle per course, code top-left then title then summary then an
enrol button, a widened sidebar so a tutorial's button never needs a
scrollbar), the redesign rounds got dramatically more accurate on the first
try. The gap I was closing wasn't in what Claude could build, it was in how
precisely I could say what "better" meant.

**What did this work change about who I want to be as a software developer?**

I used to think good process meant planning the interface fully before
writing anything. This week changed that: I'd rather ship something that
technically works, actually look at it rendered on a real screen, and only
then decide what's wrong with it. Every real improvement this week — the
full-width layout, the enrolment cap, the whole card-list redesign — came from
reacting to something deployed, not from getting the plan right up front.
That's the developer I want to be: someone who treats a working first draft
as the fastest way to find out what the right design actually is, instead of
trying to guess it correctly before seeing it.
